01Keputusan & Stack

Sembilan pilihan yang menentukan seluruh codebase.

Setiap pilihan di sini berdampak ke lusinan keputusan harian di Phase 1. Saya pilihkan tech stack yang matang, terdokumentasi, dan mendukung pertumbuhan ke Phase 2 (cloud sync, multi-user). Tidak ada hal eksperimental. Daftar singkat alternatif disertakan kalau timmu sudah punya preferensi yang kuat di kolom kanan.

02Struktur Proyek

Empat lapis. Garis batasnya tidak dilanggar.

Arsitektur 4 lapis: presentation (widget), application (provider & logic), data (repo, service, model), dan core (tema, constant). 05Network Layer

Tiga service. Bagian yang paling menentukan rasa app.

Tiga tanggung jawab terpisah: WledClient (kirim perintah HTTP), WledSocket (terima state realtime), DiscoveryService (cari wall di jaringan). Latency rendah dan reconnect yang halus = app terasa "hidup"; latency tinggi atau koneksi putus tanpa handling = produk terasa rusak.

data/services/wled_client.dart
import 'package:dio/dio.dart'; class WledClient { final Dio _dio; WledClient({required String baseUrl}) : _dio = Dio(BaseOptions( baseUrl: baseUrl, connectTimeout: const Duration(seconds: 3), receiveTimeout: const Duration(seconds: 3), )); Future<void> applyScene( Scene scene, { int? briOverride, int? sxOverride, int? ixOverride, }) async { final seg = <String, dynamic>{ 'id': 0, 'fx': scene.fx, 'pal': scene.pal, }; final sx = sxOverride ?? scene.defaultSx; final ix = ixOverride ?? scene.defaultIx; if (sx != null) seg['sx'] = sx; if (ix != null) seg['ix'] = ix; if (scene.rgb != null) seg['col'] = [scene.rgb]; await _dio.post('/json/state', data: { 'on': true, 'bri': briOverride ?? scene.defaultBri, 'transition': scene.transition, 'seg': [seg], }); } Future<void> setOnOff(bool on) => _dio.post('/json/state', data: {'on': on}); Future<void> setBrightness(int bri) => _dio.post('/json/state', data: {'bri': bri}); Future<WledInfo?> getInfo() async { try { final r = await _dio.get('/json/info'); return WledInfo.fromJson(r.data); } catch (_) { return null; } } }
data/services/wled_socket.dart
import 'dart:async'; import 'package:web_socket_channel/web_socket_channel.dart'; class WledSocket { WebSocketChannel? _channel; final _controller = StreamController<WallState>.broadcast(); Timer? _reconnectTimer; String? _ip; bool _disposed = false; Stream<WallState> get stream => _controller.stream; void connect(String ip) { _ip = ip; _channel = WebSocketChannel.connect(Uri.parse('ws://$ip/ws')); _channel!.stream.listen( _onMessage, onError: (_) => _scheduleReconnect(), onDone: () => _scheduleReconnect(), ); } void _onMessage(dynamic raw) { final json = jsonDecode(raw as String) as Map<String, dynamic>; if (json['state'] != null) { _controller.add(WallState.fromWledJson(json['state'])); } } void _scheduleReconnect() { if (_disposed || _ip == null) return; _reconnectTimer?.cancel(); _reconnectTimer = Timer( const Duration(seconds: 2), () => connect(_ip!), ); } void dispose() { _disposed = true; _reconnectTimer?.cancel(); _channel?.sink.close(); _controller.close(); } }
data/services/discovery_service.dart — mDNS + fallback subnet scan
class DiscoveryService { final MDnsClient _mdns = MDnsClient(); // Tahap 1: mDNS — cepat (~3 detik) di jaringan yang mendukung Stream<DiscoveredWall> discoverMdns() async* { await _mdns.start(); try { final ptrs = _mdns.lookup<PtrResourceRecord>( ResourceRecordQuery.serverPointer('_wled._tcp.local'), ).timeout(const Duration(seconds: 8)); await for (final ptr in ptrs) { await for (final srv in _mdns.lookup<SrvResourceRecord>( ResourceRecordQuery.service(ptr.domainName), )) { await for (final ip in _mdns.lookup<IPAddressResourceRecord>( ResourceRecordQuery.addressIPv4(srv.target), )) { yield DiscoveredWall( hostname: srv.target, ip: ip.address.address, ); } } } } finally { _mdns.stop(); } } // Tahap 2: fallback — beberapa router/mikrotik blokir mDNS, // scan paralel /24 subnet dengan probe HTTP /json/info Stream<DiscoveredWall> fallbackSubnetScan() async* { final info = NetworkInfo(); final ip = await info.getWifiIP(); if (ip == null) return; final subnet = ip.substring(0, ip.lastIndexOf('.')); final futures = List.generate(254, (i) => _probe('$subnet.${i + 1}')); final results = await Future.wait(futures); for (final wall in results.whereType<DiscoveredWall>()) { yield wall; } } Future<DiscoveredWall?> _probe(String ip) async { try { final client = WledClient(baseUrl: 'http://$ip'); final info = await client.getInfo().timeout( const Duration(milliseconds: 600), ); if (info?.brand == 'WLED') { return DiscoveredWall(hostname: ip, ip: ip, deviceId: info!.mac); } } catch (_) {} return null; } }
Strategi kontrol grup

Sesuai spec: kontrol grup di Phase 1 ditangani oleh WLED via UDP sync, bukan oleh app. App hanya kirim perintah ke satu wall di ruangan; WLED sendiri yang broadcast UDP ke wall lain dalam sync group yang sama. Cara ini menjaga latency rendah dan tidak ada kemungkinan app jadi single point of failure untuk sinkronisasi. Yang perlu disiapkan app: saat wall ditambahkan ke ruangan, set udpn.send=true dan udpn.recv=true di config wall via API. Setelah itu, app tidak campur tangan.

06State Management

Riverpod graph — satu sumber per data.

Aturannya sederhana: tiap data hidup di satu provider. Layar & widget cuma watch provider yang relevan. Modifikasi data lewat controller (notifier), yang memanggil repository, yang memanggil service. Tidak ada modifikasi state dari layar langsung.

Catatan permissions runtime

Pada Android, ACCESS_FINE_LOCATION tetap perlu request runtime dialog. Jelaskan ke user kenapa permission lokasi diminta — "Diperlukan oleh Android untuk membaca nama jaringan WiFi yang terhubung, agar app tahu wall mana yang seharusnya ada di sini." Tanpa penjelasan, user akan menolak.

Pada iOS, dialog NSLocalNetworkUsageDescription muncul otomatis saat panggilan mDNS pertama. Tidak ada API untuk request manual — kontrol-nya iOS. Pastikan deskripsi-nya jelas (di Info.plist).

10Sprint & Risk

Delapan minggu yang realistis, lima risiko yang harus dipantau.

Sprint plan asumsi tim 1-2 developer Flutter berpengalaman + 1 hardware/firmware untuk paralel. Akhir minggu 8 = MVP yang bisa dipakai sendiri di rumah; bukan release ke publik. Risiko di bawah adalah lima hal yang paling mungkin merepotkan — siapkan mitigasi sebelum kepentok.

Foundation

Setup project, dependency, theme, model Freezed (Home/Room/Wall/Scene), drift schema + migration awal. Deliverable: app launch, scene gallery dummy bisa tampil dari scenes.json.

Risk register
High
Captive portal WLED-AP di iOS sering buggy

Konteks: Saat wall pertama kali dinyalakan, dia jadi AP "WLED-AP". Connect iPhone ke AP itu seharusnya memunculkan captive portal otomatis (4.3.2.1). Pada iOS, halaman ini kadang tidak muncul atau tidak bisa menyimpan kredensial.

Mitigasi: Test di iOS sejak minggu 3. Siapkan jalur backup: instruksi tertulis di app untuk user buka Safari manual ke 4.3.2.1. Phase 2: pertimbangkan Improv BLE untuk menghindari captive portal sama sekali.

High
Tuning scene di hardware berbeda dari simulator

Konteks: 18 scene di catalog adalah titik awal yang masuk akal, tapi sx=64 akan terlihat beda di LED density rendah vs tinggi, dan brightness 255 mungkin silau di diffuser tertentu.

Mitigasi: Sediakan satu minggu khusus (minggu 8) untuk tuning di wall fisik. Hardware spec (panjang strip, LED density) harus sudah final sebelum minggu 8 — kalau belum, tuning tidak bisa dimulai dan release tertunda.

Med
mDNS tidak reliable di beberapa router

Konteks: Router cheap dan beberapa router enterprise (Mikrotik dengan isolation, mesh router dengan AP isolation) memblokir mDNS multicast.

Mitigasi: Fallback subnet scan sudah disiapkan di DiscoveryService. Trigger fallback otomatis kalau mDNS tidak menemukan apa-apa dalam 8 detik. Beri label "Sedang mencari secara menyeluruh..." supaya user tahu kenapa sedikit lebih lama.

Med
Android permission location butuh penjelasan

Konteks: Android < 12 menuntut ACCESS_FINE_LOCATION untuk membaca SSID. User awam menolak permission yang terlihat invasif tanpa konteks.

Mitigasi: Sebelum trigger system dialog, tampilkan layar penjelasan (1 layar singkat: "Android meminta permission lokasi untuk membaca nama WiFi-mu. Kami tidak membaca lokasi GPS-mu."). Setelah itu baru trigger permission_handler.

Low
User mengubah config wall via halaman web WLED secara langsung

Konteks: Power user bisa akses http://[ip-wall]/ dari browser dan mengubah segment, effect, dll. App tidak tahu hal itu terjadi.

Mitigasi: WebSocket akan mengirim state baru — kalau app sedang menampilkan layar wall, UI otomatis update. Untuk state yang berkonflik dengan record di drift (mis. nama wall diubah via web), buat resolver: app sebagai source of truth untuk nama, wall sebagai source of truth untuk state runtime.
